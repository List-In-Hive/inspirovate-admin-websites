# Inspirovate Admin

Локальная админка на Next.js и React-admin для первого полного пути публикации статьи на Petal & Stem. Интерфейс на русском, статьи сайта — на английском. Это отдельный проект: сайт Flowers собирается и работает без админки.

## Запуск на Mac

Требуется Node.js 24 (или 22.14+), Git и существующий SSH-доступ к `List-In-Hive/flowers_test`. У Git должны быть настроены имя и email для коммитов.

```bash
cd /Users/admin/Desktop/IC/inspirovate-admin
nvm use
npm ci
npm run seed
npm run dev
```

Откройте http://127.0.0.1:3100. Авторизации по запросу владельца нет. Скрипты запуска слушают только `127.0.0.1`; API проверяет Host, Origin и формат запросов. Не публикуйте эту версию в интернете и не открывайте через туннель. Для удалённого доступа сначала требуется серверная авторизация и замена локального хранилища.

Для production-сборки на своём Mac: `npm run build`, затем `npm start`. Порт тот же; остановите dev-сервер перед запуском.

## Работа со статьёй

1. Откройте «Статьи» → «Новая статья», заполните заголовок, безопасный slug, описание, дату с часовым поясом, обложку из библиотеки сайта и Markdown-текст.
2. Сохраните черновик и проверьте предпросмотр. HTML в тексте не исполняется.
3. Нажмите «Одобрить эту версию». Любое последующее сохранение сбрасывает одобрение.
4. Нажмите «Опубликовать на сайте» и подтвердите конкретную статью в диалоге. Админка создаёт файл в отдельной рабочей копии и отправляет коммит в `main` репозитория Flowers. Netlify запускает сборку через существующую Git-интеграцию.
5. Пока открыт предпросмотр, проверка выполняется раз в 20 секунд. В другое время проверка доступна кнопкой. «Опубликовано» выставляется только после проверки manifest, точного коммита, отпечатка статьи, страницы, заголовка, description, canonical и доступности обложки. Индексация поисковиками не является частью этой проверки.

`npm run seed` добавляет один пример черновика, только если хранилище пустое. Он не одобряет и не публикует материал.

## Данные и восстановление

- `.data/articles.json` хранит черновики, версии, одобрения, коммиты и результаты проверки. Запись атомарная; одновременные изменения блокируются, устаревшие версии отклоняются.
- `.data/publisher` — отдельный Git-клон для публикаций. Рабочая папка Flowers не меняется при публикации из админки.
- `.data` исключена из Git. Для резервной копии остановите админку и скопируйте `.data` в своё защищённое хранилище. Добавление исходников в Git не является резервной копией черновиков.
- После сетевой ошибки повторная отправка использует тот же файл и коммит. Существующая статья с другим ID или содержимым не перезаписывается. Git push не использует force.
- После аварийной остановки сервера может остаться `.data/operation.lock`. Сначала убедитесь, что все экземпляры админки остановлены; только затем удалите этот файл и перезапустите приложение. Активная блокировка не снимается по таймеру.
- Если Netlify не подтвердился за 15 минут, интерфейс предлагает ручную проверку. После исправления сборки используйте «Проверить публикацию». Закрытие браузера не останавливает уже отправленную сборку Netlify, но останавливает опрос её результата.

Путь к клиентскому репозиторию по умолчанию `../flowers`. При необходимости задайте `FLOWERS_REPO` в `.env.local`. Подключённый сайт, репозиторий и ветка задаются сервером в `lib/config.ts`; браузер не может подставить другую цель.

## Границы пилота

Один подключённый сайт, ручные публикации, существующие WebP-обложки. Опубликованные ранее статьи остаются в клиентском Git; список админки содержит только её собственные черновики и публикации. После отправки версия зафиксирована: правки существующих опубликованных статей пока делаются через Git. Будущая дата отклоняет публикацию; расписания нет. Нет загрузки новых обложек, AI, базы PostgreSQL, фонового worker, клиентских аккаунтов или синхронизации заявок.

Для проверки публикаций Flowers генерирует `/publication-manifest.json` во время сборки и выводит отпечаток статьи в HTML. Manifest содержит только публичные статьи и публичные идентификаторы Git/Netlify. Он должен быть доступен на сайте до первой публикации из админки. Точное совпадение коммита намеренное: если другой деплой обогнал публикацию, нужна ручная проверка, автоматического ложного успеха нет.

## Проверки

```bash
npm test
npm run lint
npm run typecheck
npm run build
```

Тесты проверяют привязку одобрения к содержимому, будущие даты, frontmatter, защиту локального API, устаревшие правки, блокировку записи и реальную повторную публикацию через временный Git-репозиторий без дублирования коммита.
